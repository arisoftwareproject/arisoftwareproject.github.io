#Show R.A.W. Value

The **Show R.A.W. Value** button opens a separate window containing raw device communication information.

This feature is particularly useful for advanced users, developers, and troubleshooting activities that require more detail than the main interface provides.

### 13.1 RAW DEVICE DATA

This section contains low-level device responses, query information, byte counts, and related diagnostic details.

The screenshot shows information such as:

- Number of enumerated battery interfaces.
- Enumeration result.
- Device opening result.
- IOCTL request information.
- Operation results.
- Number of bytes returned.
- Query input structures.
- Response buffer contents.
- Hexadecimal and ASCII representations of returned bytes.

### 13.2 Enumerated Battery Interfaces

Example:

`Enumerated battery interfaces: 1`

This indicates that one battery interface was detected during enumeration.

The enumeration result reports whether the interface discovery operation succeeded.

### 13.3 Device Open Result

Example:

`Device open result: OPENED`

This indicates that the software successfully opened the device interface for the operation shown.

Opening the interface successfully does not establish that every subsequent query will succeed or that the battery has no hardware faults.

### 13.4 IOCTL_BATTERY_QUERY_TAG

The screenshot contains a section similar to:

```
[IOCTL_BATTERY_QUERY_TAG]
IOCTL code: 0x00294040
IOCTL_BATTERY_QUERY_TAG result: SUCCESS
Bytes returned: 4
```

This request obtains a battery tag used to identify the battery in subsequent battery-interface operations.

The result indicates that the operation completed successfully according to the reported status.

### 13.5 IOCTL_BATTERY_QUERY_INFORMATION

The raw window also displays a battery information query:

```
[BATTERY_INFORMATION]
IOCTL code: 0x00294044
IOCTL_BATTERY_QUERY_INFORMATION: SUCCESS
Bytes returned: 36
Response validation: COMPLETE
```

This section records the result of a battery information request, including the number of bytes returned and the software's response-validation status.

A successful query indicates that the request returned successfully. It does not independently validate the physical condition of the battery.

### 13.6 Query Input Structure

The query input structure contains the bytes sent to the device interface as part of the request.

Its interpretation depends on the specific IOCTL operation, the expected input structure, and the relevant Windows battery-interface definitions.

### 13.7 Response Buffer

The response buffer contains the bytes returned by the device or driver.

The window displays these bytes in hexadecimal form, alongside a printable ASCII representation where applicable.

This information can help developers inspect responses, troubleshoot unexpected results, and verify whether a request returned the expected amount of data.

Raw values should not be interpreted as standalone measurements without understanding the associated structure, field offsets, data types, and byte order.

### 13.8 Benefits of the R.A.W. Value Feature

The raw-data window can help users:

1. Verify whether a battery interface was detected.
2. Inspect device-opening and query results.
3. Check response sizes and validation status.
4. Investigate missing or unusual battery information.
5. Examine low-level responses during software debugging.
6. Gather technical information for further analysis.

This feature is intended for technical inspection rather than everyday battery monitoring.
